# STA 移动端交互与通知公告方案

状态：部门点击展开已在本地实现；全站动效增强与公告系统为待实施方案。

交互设计稿已提供在 `design/notice-lab/`：基于真实主站及其云端文案，可切换电脑/手机，体验公告纸层展开、图文阅读、多图放大与部门书封。此设计稿尚未接入真实公告发布。

## 设计依据

沿用主站的浅蓝白底、深蓝文字、钴蓝强调色、Space Grotesk 英文及现有中文字体。保留棱影飞镖开屏、部门书封、活动图像和圆形箭头，让新增交互属于同一个站点。

本次为局部演进，设计变化/动效/密度参考值为 7/6/4。动效主要承担点击反馈、展开内容、引导阅读顺序；手机端不增加持续跟手粒子或滚动锁定。

## 已实现：部门书封适配触摸操作

- 点击整行部门标题区，展开该部门的书封、宣言和方向标签；再次点击收起。同时仅展开一个。
- 书封采用约 480ms 的轻微转入，文字约 360ms 淡入上移，箭头同步旋转并填色。展开区域留在正文中，浏览时可以继续正常滚动。
- 切换部门时保持被点击标题的位置，并刷新后续滚动动效的触发位置。
- 桌面保留悬浮书封，点击也可固定展开阅读；键盘 Enter/Space 操作按钮，Escape 收起。按钮带展开状态和关联区域。
- 开启系统“减少动态效果”时直接显示内容。书封、宣言和标签使用主站已解析的同一份云端内容。
- 鼠标离开部门后停止悬浮预览的动画帧循环。

## 规划：手机端动效增强

| 场景 | 交互与动效建议 | 实施边界 |
| --- | --- | --- |
| 按钮、菜单入口 | 按下缩至 0.98，松开回弹，约 120–180ms | 仅用于能执行操作的元素，最小点击区域 44px |
| 正文入场 | 标题、正文分组一次性淡入，上移 12–18px，约 320–450ms | 现有约 1 秒、44px 的正文入场在手机上缩短，反向滚动不重复播放 |
| 近期活动 | 保留原生横滑和吸附，补当前项指示与短暂的选中态变化 | 按实际横滑位置更新；不自动轮播，不把纵向滚动转成横向 |
| 加入我们 | 报名步骤进入视口时依次显现，连接线对应实际阅读进度 | 二维码和报名链接立即可用，动效不延迟信息可见性 |
| 菜单 | 保留现有展开语言，菜单项以较短间隔依次显现 | 新增公告入口后保证矮屏可滚动、关闭后焦点返回菜单按钮 |
| 开屏 | 先实测手机帧率，再决定是否降低粒子量和像素倍率 | 保留已确定的第六版视觉叙事；暂不改变时长和播放策略 |

验收覆盖窄屏、普通手机、平板、横屏、触摸与鼠标混用、减少动态效果。信息型内容静止后应停止动画，入场效果不影响阅读和点击。

## 规划：通知公告

### 位置与内容职责

在首屏后的现有分隔带与“关于科协”之间增加“通知公告”。它承担正在发生或需要行动的信息，如招新报名、讲座时间、征稿、结果公示；“近期活动”继续承载活动回顾和照片。

导航提供公告入口，首页优先展示一条置顶或最新的重要公告，再列出三条最新公告，提供“全部公告”。无发布内容时收起首页板块及其入口；公告归档页使用明确的空状态。

### 电脑与手机布局

- 桌面采用主次分明的编辑式公告板：左侧重点公告及可选图片，右侧紧凑列表。列表显示类别、发布日期、标题和有效状态，信息不依赖悬浮才能看到。
- 手机将重点公告置于顶部，后接纵向标题列表。重点公告没有图片时使用文字版式，不补虚构海报。
- 图片区域预留尺寸。海报完整展示，尤其保留时间、地点与二维码；摄影封面可选裁剪焦点。即便图片载入失败，标题、时间、摘要和操作链接仍可阅读。
- 类别筛选先保持简单：全部、招新、活动通知、公示；实际类别由后台管理，不为凑分类创建公告。

### 图文详情与图片查看

公告使用可分享的独立详情地址。详情包含标题、发布日期、发布部门、正文、可选行动链接，并支持在正文中穿插多张图片、图注与替代文字。

图片轻触后全屏查看，支持放大、移动、切换多图和明确关闭按钮；手机保留自然缩放手势。返回公告列表恢复原筛选和浏览位置。报名二维码可放大并提供查看原图入口。第一期支持图片与链接，附件下载可作为后续扩展。

### 动效建议

- 板块进入视口时，重点公告先出现，列表以约 40ms 间隔依次淡入，每项约 320ms，只执行一次。
- 桌面重点图片悬浮轻微放大至 1.025；手机点击压下反馈。标题与发布日期保持稳定。
- 类别切换约 160ms 淡出/淡入，并通知辅助技术结果数量；减少动态效果时立即切换。
- 图片查看以约 220ms 淡入和轻微缩放建立层次，关闭时反向过渡；详情正文不做逐字动效。
- 置顶、已截止等状态由文字和样式表达，不采用持续闪烁或自动滚动公告。

### 云端与后台落地方式

复用现有后台会话与图片上传流程。为公告建立独立内容集合，包含稳定 ID、标题、摘要、分类、发布部门、正文块、图片（地址/尺寸/替代文字/图注）、行动链接、置顶、状态、发布时间及可选截止时间。

草稿必须由服务端限制访问，公开读取接口只返回已发布内容；不能把草稿放进公开可读的主页 JSON 再靠前端隐藏。后台需要支持预览、保存草稿、发布、撤回、置顶与归档；上传入口复用现有格式和大小校验，正文限制为安全的受控文本/图片块。

每次编辑基于云端最新版本，提交携带版本条件以识别同时编辑冲突；公告发布不整体覆盖主站文案。图片采用缩略图与原图分工、按需载入，尺寸预留避免页面跳动。截止状态由实际时间计算，历史公告仍可查看。

## 实施顺序

1. 完成部门触摸交互并验收。
2. 将移动端正文入场、操作反馈、活动横滑指示作为一轮局部增强。
3. 定义公告云端结构与访问权限，完成后台发布、主页展示、归档和图文详情。
4. 完成图片全屏查看及动效，验证未发布内容不可公开读取、过期状态和移动端阅读。

公告验收必须使用真实发布资料；开发演示内容明确标记，不能冒充真实通知发布。
